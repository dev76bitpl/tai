# Wzory dokumentów

Wypełnione przykłady pokazujące **poziom szczegółowości i format** dokumentów projektu.
To nie są dokumenty tego projektu — opisują zmyślony system zamówień.

| Wzór | Dla którego dokumentu | Co pokazuje |
|---|---|---|
| [SETUP.example.md](SETUP.example.md) | `docs/SETUP.md` | wymagania z wersjami, kroki z poleceniami i oczekiwanym wynikiem, pułapki z prawdziwych problemów |
| [TASKS.example.md](TASKS.example.md) | `docs/TASKS.md` | log sesji: wpis na domknięty krok, dwie warstwy opisu, nazwane dygresje |
| [ROADMAP.example.md](ROADMAP.example.md) | `docs/ROADMAP.md` | faza = cel, zakres, weryfikowalne „done when”, zależności |
| [ADR-001-example.md](ADR-001-example.md) | `docs/adr/ADR-NNN-<temat>.md` | kontekst, decyzje z uzasadnieniem, odrzucone alternatywy, konsekwencje |

**Jak z nich korzystać:** zanim napiszesz albo rozbudujesz któryś z tych dokumentów, przeczytaj
jego wzór. Wzorów się nie edytuje i nie usuwa — zostają jako odniesienie na cały czas życia projektu.
Zasada jest w `CLAUDE.md` (sekcja „Zarządzanie artefaktami projektu”).
